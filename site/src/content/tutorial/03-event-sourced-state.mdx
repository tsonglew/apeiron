# 第 3 章 · 状态与持久化：事件日志 + (session_id, seq) CAS

> 对应真实代码：[`entries.zig`](/apeiron/docs)、[`log.zig`](/apeiron/docs)、[`store.zig`](/apeiron/docs)、[`harness.zig`](/apeiron/docs)。

## 3.1 事件溯源：一问一答

- **唯一源真是谁**？会话的**不可变事件序列**（Entry 列表）。"当前对话"是它的投影；
- **为什么不可变**？可变状态跨进程同步是泥潭；追加日志只需要一个"追加"原语；
- **为什么带树**？`parent_id` 让 fork / 重试 / 子代理全部免费——全是树操作，没有新机制。

Entry 的字段（`entries.zig`）：

```zig
pub const Entry = struct {
    session: SessionId,   // 会话 id
    seq: u64,             // 会话内单调递增 —— 乐观并发控制的唯一依据
    entry_id: EntryId,    // uuid4 hex
    parent_id: ?EntryId,  // 树式历史
    author: Author,       // user/model/tool/hook/system
    kind: EntryKind,      // user/assistant/tool_call/tool_result/summary/checkpoint
    payload: std.json.Value,
    schema_version: u32,  // 演进靠版本化，不破坏旧存档
};
```

## 3.2 单写者：把正确性压缩成一个约束

不做 CRDT、不做分布式锁协议——**从模型上消灭并发**：

> 每个会话同时只有一个写者；写 = 追加一条带单调 `seq` 的 entry；
> 存储层用 `(session_id, seq)` 主键/唯一索引天然做成 CAS。
> 多写者并发写同一会话时，后者收到 `SeqConflict`——这是特性，不是 bug。

本地版单写者 = harness 的 `prompt` 守卫（`phase != idle` 抛 `HarnessBusy`，对应 pi 的 LaneBusy）；
分布式版 = lease（M2）。中间的"恢复"就是：**从存储重放 head 之后的日志**：

```zig
pub fn resumeSession(self: *Harness, session: *Session) anyerror!void {
    const head = session.log.head();
    const since = if (head) |h| h.seq else 0;
    const stored = try self.store.entries(self.alloc, session.session_id, since);
    try session.log.restore(stored);                      // 所有权移交 log
    // 重建 messages（模型视角的投影）
    const rebuilt = try loop.messagesFromLog(self.alloc, session.log.entriesSince(0));
    ...
}
```

## 3.3 防御式编程：Zig 里的所有权

Python 有 GC，Zig 没有——这本教程的每个"踩坑"都该被记住：

- `StringArrayHashMap` 不复制 key：`put` 前必须 `dupe`，否则 `deinit` 会去 free 静态内存；
- entry 的 `session` 是所有条目共享的**借用引用**（归 SessionLog 所有），`entryDeinit` 不释放它；
- `defer free(x); return x;` —— **返回的切片在返回前被释放**，调用方读到垃圾字节；
- `errdefer` 的作用域：已经移交给容器的对象，不能再被它释放（双释放）。

（每一条都真实发生过，对应 fixed commit——读 `git log` 里的修复就能学到。）
